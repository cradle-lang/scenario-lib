# Repository instructions

## Pull requests

When drafting, creating, or updating a pull request:

- Read `.github/pull_request_template.md` and use it as the single source of truth for the PR description.
- Preserve its headings and complete every section, including the validation table and submission checklist.
- Describe the actual changes, their purpose, and any relevant requirements based on the diff and available evidence.
- Replace placeholders and instructional prose with concrete details. Mark irrelevant fields and checklist items `N/A` and explain why, including scenario-specific items for repository tooling or documentation changes.
- Record actual validation results. State which checks were not run and why; distinguish repository checks, compilation, and runtime exercise evidence.
- Check checklist items only when verified. Leave incomplete items unchecked and explain any remaining work.
- Include known limitations and reviewer notes, or write `None` when there are none.
- When creating or updating a PR through a CLI or API, explicitly supply the completed template as the PR body.
